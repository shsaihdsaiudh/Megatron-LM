## 正文

## 概要

在实验性的 Megatron-FSDP（v2）路径中，把最后一个 microbatch 的 DP-outer 梯度归约与
DP-inner 归约重叠，置于可选的 `overlap_outer_communication` 开关之后。延续 #6714
（#5616 的子 issue）。

目前 DP-outer finalize（HSDP all-reduce / HFSDP reduce-scatter）运行在
reduce-scatter stream 上，串行排在 DP-inner 归约之后。本次改动把它路由到自己的
stream，从而使一个参数组的 DP-outer 归约可以与下一个组的 DP-inner 归约重叠。

## 设计

可选的 `overlap_outer_communication` 开关为最后一个 microbatch 的 DP-outer 归约提供
一条专用 stream。它通过 `--overlap-outer-communication` 暴露。关闭时，outer 归约与
`inner_reduction_stream` 共用；开启时会创建专用的 `outer_reduction_stream`。

`overlap_allgather_reduction=True` 在 `RuntimePolicy` 中取代
`unify_communication_stream=False`，保留 all-gather 与 reduction stream 分离的默认
行为。设为 false 则共用这些 stream。两个重叠选项相互独立：四种组合都支持。Outer
all-gather 分离属于未来工作；本 PR 实现的是 outer reduction 重叠。

把梯度归约拆分为 `reduce_inner_gradients()` 和 `reduce_outer_gradients()`。模块在每个
组的 inner 归约之后为 outer stream 建立顺序依赖，使得后续组可以在 outer 通信运行时
打包并归约自己的梯度。两条路径都复用现有的持久 `main_grad` 缓冲及其优化器布局视图
`pre_optimizer_main_grad`；不引入额外的梯度缓冲。

rebase 后的实现使用 `context.py`，并在 `finish_grad_sync()` 中汇合两条归约 stream，
同时覆盖自动同步和调用方管理的同步。adapter 和两个共享训练上下文工厂都通过
`RuntimePolicy` 传递该选项。

## 测试

已 rebase 到 `origin/main` 的 `2d7ea246f`，保留 main 的 recorded-prefetch 顺序和
SchedulePolicy 改动。两个共享训练上下文工厂仍然通过 `RuntimePolicy` 传递 outer 重叠。
归约调度方法、参数组实现和 runtime-policy 定义与已评审的 head 一致。

在两块 RTX A6000、NGC 26.08 上，**每个 rank 142 passed、6 skipped**，覆盖 context、
fully-shard、overlap、memory、MCore CUDA graphs、梯度多重性、dense/MoE adapter 和
参数相关测试。这覆盖了串行/重叠的 HSDP 与 HFSDP 训练，包括两种分片布局、两种
`zero_grad` 模式、1/3 个 microbatch，以及全部四种 stream 选项组合。

Black、isort、Ruff、Pylint（10/10）和 `git diff --check` 在仓库的 formatter 范围内
通过；修改后的训练入口也能编译。跳过的用例需要 4 个 rank 或 Blackwell 硬件。本地
hybrid mesh 是 2x1；两个 mesh 轴上的非平凡通信和多节点性能尚未重新验证。本地测试使用
NGC 26.08；标准 CI 使用 NGC 26.09。GitHub CI 在 rebase 后的 head 上尚待运行。

## 测量

当 DP-outer 和 DP-inner 映射到不同通信通道（例如 RDMA vs NVLink）时，这种重叠才有收益。
在单节点硬件上两个轴都是 NVLink；那里的集合通信重叠微基准能找回 DP-inner + DP-outer
合计集合通信时间的大约 1/3。真实多通道配置上的影响最好在更大的硬件上测量。
