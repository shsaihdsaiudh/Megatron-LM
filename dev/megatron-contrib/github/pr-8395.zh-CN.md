## 正文

最后一个 microbatch 的 DP-outer 归约目前与 inner reduce-scatter 共用同一条 stream。
下一个参数组在打包梯度之前要等待该 stream，因此一次耗时的 outer 归约会卡住反向计算。

该 PR 把延迟执行的 DP-outer 归约移到一个由 FSDP context 拥有的专用
`outer_reduce_scatter_stream`：

在启动 outer 通信之前，先等待产生依赖的 inner 归约完成。
允许后续的梯度打包和 inner 归约在 outer 通信运行期间继续推进。
在 `finish_grad_sync()` 中汇合两条归约 stream，然后再消费最终梯度。
在反向入口建立 outer stream 依赖，以便 CUDA Graph 捕获。
将融合的 expert 梯度缩放保留在最终完成梯度的 stream 上。
该改动保留现有的 `reduce_partial_gradients()` API、持久梯度缓冲以及 all-gather 路径。

验证情况

- 完整 MFSDP v2 单元测试套件通过，包括 CUDA Graph 和 stream 同步相关覆盖。
- 组合后的优化栈在 128 张 GB200 GPU 上完成了 20 次 DSv4 Flash HSDP 迭代，启用了
  整迭代和优化器 CUDA Graphs，没有出现跳过迭代或 NaN 迭代。
- 与 #6973 相关，后者针对同一个重叠机会。本实现保留现有梯度归约 API，并在最后一个
  microbatch 的分支内完成 stream 切换。
