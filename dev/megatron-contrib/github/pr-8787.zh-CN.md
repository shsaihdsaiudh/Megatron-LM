# 这个 PR 做了什么？
启用 `hfsdp_param_gather_overlap` 时，一个比剩余预取尺寸更大的 DP-Outer bucket 可能
在下一个 FSDP unit 中途结束 DP-Inner 预取窗口。该 unit 剩余的部分只能在它自己的
pre-forward hook 中 gather，落在关键路径上。现在窗口会把它所结束的那个 FSDP unit 走完，
最多因此多出一个 unit 的尺寸，且绝不会继续往后走。

### frontier FSDP unit 内部的空洞

新的 [completion helper](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L4700-L4720) 假设到达最大/最小被选中的 bucket 就意味着中间所有 bucket 都被选中。这并不成立：[parameter groups 会区分 dtype](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L1848-L1884)，而 [collective groups 按 unit 和 expert 状态合并 bucket](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py#L1999-L2025)。因此，一个依次注册 dense FP32、expert FP32、dense FP16 参数的 unit，可能出现 interleaved 的 dense collective group。

**失败场景：** 使用 `unit_ids=[0,1,1,1,2]`、尺寸 `[6,20,6,6,6]`、bucket groups `{0:[0],1:[1,3],2:[2],3:[1,3],4:[4]}`。在开启 overlap、prefetch 和 DP-Outer gathering 的情况下，以预算 10 请求 bucket 0 会让尺寸扩展返回 `[0,1,3]`。新 helper 从 bucket 3 之后开始、止于 unit 2，结果 bucket 2 没有被 gather。于是 DP-Inner 仍然要在自己的 hook 里 gather unit 1 的那部分，而不是预取整个 unit。反向从 bucket 4 遍历时同样会让 `[1,3,4]` 不完整。

**修正：** 在选中区间内补齐 frontier unit 缺失的 bucket，同时补齐它的方向性尾部。保持 bucket-group 的原子性包含，且不额外增加 unit。建议在现有 `while` 循环之后、最终 return 之前插入：

```python
        for bucket_id in range(min(result), max(result) + 1):
            if (
                bucket_id not in result
                and parameter_groups[bucket_id].fsdp_unit_id == fsdp_unit_id
            ):
                result.update(self.buffer.bucket_to_bucket_group[bucket_id])
```

现有的 `None`-frontier 提前返回应保留。跳过已被选中的 bucket 很重要：否则一个只包含
bucket 3 的细粒度请求可能会不必要地把已有的 collective group 扩展到 bucket 1。该补丁
基于源码推理，采用前必须验证。

**验收与保留：** 按上述映射新增前向/反向流水线回归测试。期望 DP-Inner 前向为
`[0,1,2,3]`、反向为 `[1,2,3,4]`；DP-Outer 在两种情况下都应包含全部五个 bucket。还要
断言仅 helper 的局部请求 `[3]`（前向）和 `[1]`（反向）保持不变。保留
[现有回归用例](https://github.com/NVIDIA/Megatron-LM/blob/5e9f02611a020c650402455f678cb18803027a0e/tests/unit_tests/distributed/mfsdp_v1/test_mfsdp_fully_shard.py#L275-L431)：连续的前向/反向完成、非 unit 的 frontier 不变、零尺寸 `inner=[0]`/`outer=[0,1,2]`、双缓冲 `inner=[0,1,2]`/`outer=[0,1,2,3,4]`、关闭 overlap 时 `inner=[0,1]` 且不启动 outer、关闭 outer gather 时 `inner=[0,1,2,3,4,5]` 且不启动 outer。
