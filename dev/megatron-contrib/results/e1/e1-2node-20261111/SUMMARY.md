# E1 结果：MFSDP v2 HFSDP baseline 下 DP-outer all-gather 的暴露量

- 任务 `t-20261111170448-tecw8`，2 × 8 H20，mesh (2,8)，outer 跨节点走 IB/RoCE，inner 走 NVLink。
- 代码：main `d2b0e35cc`，未修改。环境：Python 3.12.16，torch 2.14.1+cu130，NCCL 2.30.7。
- 脚本：`bench/e1_exposure.py`，入口 `cml/e1_entry.sh`。原始数据在 `e1_d4096_L32.json`、`e1_d8192_L16.json`，
  nsys 报告在 `nsys/`，统计脚本是 `bench/e1_nsys_stats.py`。
- 模型：N 个残差 MLP block（`x + W2·gelu(W1·x)`，每块 8d² 个参数），bf16 计算权重，fp32 main weight，
  每个 block 和 root 各调用一次 `fully_shard`，placements 用 HFSDP，默认 prefetch（提前一个模块）。
- 计时：在计算流上用 CUDA event，先在每个 rank 上取 8 个测量 step 的中位数，再在 16 个 rank 中取最大值。
- E = T_fwd(mb0) − T_fwd(mb1..)。对照组 `nostep` 跳过 `optimizer.step()`，这样 mb0 不做 outer AG。

## 暴露量 E（ms）和占 step 的比例

N·O 和 N·min(O,I) 用的是 E0 的单块测量值，d=4096 时 O=0.762、I=0.722；d=8192 时 O=2.800、I=2.724。

## 观察

1. **E 可以归因到 outer AG。** 对照组 nostep 的 E 只有 0.4–6.9 ms，并且随 T 增大而增大，可能是第一个
   microbatch 自身的效应。train 模式的 E 是它的 4–40 倍。E 在 16 个 rank 之间的差异小于 1.5 ms，
   各 step 之间也很稳定。
2. **T ≤ 256 时，outer AG 基本上完全暴露**：E ≈ N·O（23.2 对 24.4，43.9 对 44.8）。这时即使只有
   inner AG 也已经受通信限制，nsys 显示 T=256 时 mb1 有 7.5 ms 空泡。
3. **T 很大时 E 也没有降到 0。** 这和计划里的预期不一样。d=4096、T=4096 时，每层计算约 8 ms，
   远大于 O+I ≈ 1.5 ms，但 E 仍然有 16 ms，大约是 N·O 的 65%。d=8192 时是 28 ms，约 63%。
   不过因为 step 本身很长，比例只有 0.2–2%。
4. **原因（nsys，T=1024，d=4096，rank 8）：NCCL kernel 只能在 GEMM 的尾部开始执行。** H20 有 78 个 SM，
   cuBLAS 的 nvjet GEMM 会占满所有 SM。整个 trace 里有 594 个 all-gather kernel，其中 555 个是在
   GEMM 运行期间开始的，而且全部落在 GEMM 进度的 60–100% 区间，大部分在最后 20%。在 mb0 里，每层的
   O 只能在 fc1 的尾部开始，I 只能在 fc2 的尾部开始。I 结束得比 fc2 晚大约 0.44 ms，下一层的
   计算就要等这段时间，32 层 × 0.44 ≈ 14 ms，和 E 吻合。mb1 只有 I，它在 fc1 的尾部就能开始，
   所以没有空泡（T=1024 时 mb1 只有 1.3 ms 空泡）。
5. 计算的 CPU 侧不是瓶颈：mb0 forward 的 CPU 区间是 28 ms，而 GPU 是 92 ms，kernel 的发射延迟一直在增长。
   AG stream 上的空隙是 GPU 端在等待，原因是 SM 不够用，不是依赖关系。

## 对 E2 的含义

- 收益上限：T 小时约等于 N·O，在 GA=1 时占 step 的 17–19%；T ≥ 1k 时是 14–35 ms，在 GA=1 时占 2–6%，
  GA=8 时不到 1%。
- 只把 outer AG 放到单独的 stream 上，未必能收回 T 大时的那部分 E。在 SM 被 GEMM 占满的情况下，
  O 和 I 仍然要等 GEMM 尾部空出的 SM。两条 stream 的好处是 O 和 I 可以在同一个尾部窗口里一起启动，
  E0 证明它们并行时几乎不互相拖慢。实际能收回多少要在 E2 里测。
- E2 值得加的一个变体：通过 cuBLAS 给 GEMM 预留 SM（SM carveout），看 baseline 的 E 本身会不会下降。
  这能帮助区分两种情况：问题出在 O 和 I 串行，还是出在 SM 被抢占。

## 局限

- nsys 只开在 rank 0 和 rank 8 上，开启后这两个 rank 的时序会和其他 rank 错开（rank 0 的第一个 AG
  等了 340 ms），所以 nsys 运行只用来看时间线的形状，不用来计时。计时用的是另一次没开 nsys 的扫描。
- 模型只是 MLP，没有 attention 和 norm；GEMM 形状单一。真实模型的 kernel 更碎，SM 空隙更多，E 可能更小。
- 只测了 H20 2×8，没有和单节点 mesh (2,4) 的对照。
